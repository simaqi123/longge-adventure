## 这是什么

大部分人做个人项目失败的原因不是不努力，是**不知道钱从哪来、卡在哪、什么时候该停**。

这个仓库把这件事拆成了一张能看的图：

| 你以为在做的 | 实际在做的 |
|---|---|
| 做内容 | 10 个位次，每个位次有专属素材池、工序链、瓶颈标记 |
| 找选题 | 素材互斥分摊，Σ 独占素材 ≡ SSOT 条目总数，一分不虚 |
| 熬内容 | 工序链逐步展开，哪道工序吃掉你 25% 以上精力自动标红 |
| 想收入 | 变现链路三层：内容拉新 → 私域沉淀 → 订阅收现金 |

核心不是那张图，是**图下面那套东西**：一个能跑、能校验、能注入测试的生成管线。
页面上每个数字都能回溯到数据层的某个具体条目，改错了校验器会拦下来。

## 三分钟跑起来

```bash
git clone https://github.com/simaqi123/longge-adventure.git
cd longge-adventure

# 1. 校验数据（应该 0 错误）
python scripts/validate_ssot.py data/养生知识表.csv

# 2. 生成生存地图 → web/养生一人公司生存地图.html（双击即开）
python scripts/build_survival_map.py

# 3. 生成体质自测 → web/体质自测.html
python scripts/build_constitution_test.py

# 4. 全套校验（结构 / 口径 / 合规）
python scripts/validate_survival_map.py
python scripts/validate_deep_model.py
python scripts/validate_constitution_html.py

# 5. 注入测试：故意破坏页面，确认校验器能抓住（44/44）
python scripts/test_survival_map_injection.py
```

无依赖，Python 3.8+ 标准库即可。生成的 HTML 是**单文件零外部依赖**，双击就能离线打开。

## 三条结构不变量

这是整套东西的地基。改代码可以，破坏这三条就是缺陷。

**① `Σ 独占素材 ≡ SSOT 实际条目数`**
每个主题只归属**一个**主位次，其余位次记进共享池，不重复占面积。
v2 版本没做这件事，十个位次面积加起来 569，SSOT 实际只有 205——同一批素材被算了 2.8 遍，
treemap 面积彻底失真，"面积大＝这个位次大"的读图前提直接不成立。

**② 面积口径唯一：月产出件数**
v2 混用了素材条数和产出件数两种单位，不可比。v3 统一由工序链残余工时推导，
十个位次同单位、可比、可复算。素材条数降级为独立的「独占素材」指标。

**③ 必须且仅有一个现金出口**
线下诊疗服务停办后，全图一度没有现金出口——一个"生存地图"却没有一条通向钱的路径，说不过去。
所以结构固定为：**6 个素材位次 + 3 个成品出口 + 1 个现金出口 = 10 位次**。

## 中医赛道特有的一道坎

做医疗内容的人抄这套「早报 + 选题 + 私域」会直接踩雷：

> 《互联网广告管理办法》第八条：介绍健康、养生知识的，**不得在同一页面或同时出现**相关医疗、药品、保健食品的商品经营者或服务提供者地址、联系方式、购物链接。

所以陈磊那套「早报卡片带引导话术 + 引导加微信」在中医赛道**不能直接用**。
本仓库的处理是**结构性分离**：

```
科普内容（公众号 / 视频号 / 小红书）
    └── 纯知识，无联系方式、无购买链接、无"加我咨询"
              ↓
私域沉淀（微信群 / 知识星球）
    └── 群内才是转化场景，但群内内容按"服务介绍"而非"科普"定性
              ↓
线下服务（已停办，不再是交付路径）
```

这套边界不是写在文档里提醒你注意的，是**写进校验器**的：

- `validate_ssot.py` — 20 类红线：禁用医疗用语、功效断言、特定人群限定、问诊诱导、侵入性技术、处方药材
- `validate_constitution_html.py` — 结果页 16 类扫描：手机号、微信号、外链、二维码、扫码引导……一个都不许有
- `test_survival_map_injection.py` — 44 条注入用例，故意破坏页面确认校验器拦得住

**合规在这个仓库里是可执行的，不是免责声明。**

完整红线清单见 [`docs/合规边界手册.md`](docs/合规边界手册.md)。

## 数字的可信度分层

页面上每个数字都标了属于哪一层。不标这一层的数字一律不上页面。

| 层级 | 含义 | 例子 |
|---|---|---|
| **可核验** | 来自 SSOT 与脚本实跑，逐条可回溯 | 素材条数 205、节气覆盖 24/24、工具化率 |
| **口径值** | 行业锚点推导，**非实测**，可被真实记录覆盖 | 单件工时、有效产出系数 0.55、瓶颈阈值 25% |
| **不推算** | 明确不做 | 收入、转化率、成本预测 |

有效产出系数 0.55 这一层最关键：一人公司的时间不只花在"做内容"上——多平台分发与排版适配、
评论私信回复、数据回看与选题调整、素材补充与工具维护，以及状态波动。
单条工序链只占约 55% 工作时间。**不扣这一层，算出来的产能会显著高于实际可达水平**（初版算出"每周 48 件"，失真）。

推演区不含任何收入数字。没有真实定价、转化和续订数据时，任何收入推算都是虚构。
校验器会拦截「预计月入」「保底收入」，也会拦截把工时说成"实测"的表述。

详见 [`docs/深度经营模型-口径声明.md`](docs/深度经营模型-口径声明.md)。

## 90 天路线

| 阶段 | 目标 | 出口条件 |
|---|---|---|
| 1 · 第 1–30 天 | 跑通生产：素材转内容 | 连续 4 周按节奏产出，每条带出处与免责 |
| 2 · 第 31–60 天 | 找瓶颈：砍掉最贵的工序 | 每道工序工时被真实记录覆盖，瓶颈判定有据 |
| 3 · 第 61–90 天 | 建通路：内容 → 私域 | 早报订阅有真实留存，工具使用能对应到订阅者 |
| 4 · 第 91–180 天 | 收现金：陪伴转订阅 | 续订意愿能被记录，而非只统计一次付费 |

每条阶段都绑定了**可观测的判据**，未达成时页面会写明下一步该做什么，不由模型编数字。

## 这套东西怎么复用到别的方向

架构是通用的，养生只是第一个跑通的样本。

| 层 | 换成你自己的方向要改什么 |
|---|---|
| 数据层 | 换成你的 SSOT 表（字段规范见 `docs/契约层.md`） |
| 角色层 | 改 `survival_map_data.py` 的 `ROLES` 与 `THEME_OWNER` |
| 执行层 | 换 `TOOL_EVIDENCE` 指向你自己的脚本 |
| 合规层 | 换成你所在行业的红线词表与校验器 |

`THEME_OWNER` 是唯一需要动脑的地方——它决定了面积口径能不能守恒。
新增位次时，先想清楚你的新主题归谁，然后保证 `Σ area ≡ SSOT 条目总数` 这条恒等式不破。
校验器会替你盯这条。
