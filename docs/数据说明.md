## 二、三条写入纪律

### 2.1 内容要点必须去医疗化

`内容要点` 里禁止出现：

- 疾病治疗表述（治疗 / 根治 / 治愈 / 专治 / 防治）
- 医疗行为表述（消炎 / 杀菌 / 排毒 / 祛湿 / 活血化瘀 / 滋阴补阳 / 疏通经络）
- 功效断言（养心安神 / 健脾 / 补气 / 降压 / 增强免疫 …共 52 项）
- 特定人群限定（孕产 / 术后 / 婴幼儿 / 康复期 / 化疗 / 放疗 …）
- 问诊诱导（哪里不舒服 / 什么症状 / 开方 / 帮我诊 …）

**规则**：只说"做什么"和"什么体感"，不说"治什么病"和"效果多好"。

### 2.2 出处必须可溯源

出处只有三种形态：

| 形态 | 举例 | 是否公开可核验 |
|---|---|---|
| 古籍原句 | `《素问·四气调神大论篇第二》：「春三月，此谓发陈……」` | ✅ 可核验 |
| 公开标准 / 法规 | `《中医九种体质》标准`、`中医养生保健服务规范(试行)` | ✅ 可核验 |
| 主题级资料 | `慢病主题资料·慢病合集` | ⚠️ 内部资料，仅记方向 |

**不允许空出处，也不允许填 `NONE`。**

### 2.3 食材清单必须标归属

每味食材必须带真实归属标签，与 `data/食药清单.json` 一致：

| 标签 | 含义 |
|---|---|
| `食药清单内` | 在卫健委《既是食品又是药品的物品名单》内 |
| `保健食品级` | 在《可用于保健食品的物品名单》内 |
| `普通食品` | 公告明确的普通食品 |
| `普通食材` | 日常农作物 / 畜禽 / 水产 / 调味 |

**标注不实会被校验器拦下**。另外：

- 公告明确「不是普通食品」的物质，任何渠道都不得作食材
- 「仅限作香辛料和调味品」的 6 种，不得作为主要食材，必须带 `·仅限香辛料` 限定
- 处方药材（柴胡 / 黄芩 / 附子 / 麻黄 / 桂枝 / 大黄 / 半夏 / 细辛 …）一律不得出现

## 三、脱敏处理

本仓库发布的是**公开发布版本**。原始语料与内部结构**不在仓库内，也不在公开范围内**。

### 3.1 处理了什么

| 类别 | 处理方式 |
|---|---|
| 机构名称 | 替换为「非诊疗类养生服务机构」等中性表述 |
| 价格信息 | 全部移除 |
| 经营词（价目表 / 会员卡） | 替换为「服务项目清单 / 服务套餐」等中性表述 |
| 内部段落编号（`段4` / `段29` / `段41` …） | 归一化为「主题条目 / 主题段落」 |
| 私有语料文件名 | 归一化为「慢病主题资料·<方向>」，保留病种方向（公开医学常识），去掉内部编号 |
| 内部经营色彩的服务名 | 归一化为「温热灸服务 / 砭石温敷服务 / 全身推拿服务 / 拔罐服务 / 养生咨询服务」 |
| 本地路径、跨项目信息 | 全部清除 |

### 3.2 保留了什么

- **条数守恒**：205 条，一条不少、一条不多。下游生存地图的面积口径依赖这个数字
- **字段结构**：11 个字段完整保留
- **主题分布**：8 类分布不变
- **公开可核验出处**：古籍原句、公开标准、公开法规原样保留
- **食材归属标注**：逐条保留，可与 `食药清单.json` 交叉核验

### 3.3 脱敏器是仓库的一部分

`scripts/sanitize_for_public.py` 不只是一个一次性脚本——它**自带泄漏自检**：

```bash
python scripts/sanitize_for_public.py --in 你的原始表.csv --out data/养生知识表.csv
```

流程：

1. 字段级替换（机构 / 价格 / 经营词 / 内部编号 / 私有文件名）
2. **条数守恒断言** —— 脱敏绝不改变条目数
3. **泄漏自检** —— 15 类正则 + 出处白名单双重扫描
4. **自检不通过即中止，不写出文件**

这个设计是有意的：**公开版必须是脚本生成的，不是手工改出来的**。
手工脱敏无法保证可重复，也无法证明没漏。

## 四、怎么改这张表

1. 改 `data/养生知识表.csv`（这是 SSOT，唯一写入点）
2. `python scripts/validate_ssot.py data/养生知识表.csv` → 必须 0 错误
3. `python scripts/build_survival_map.py` → 重建生存地图
4. `python scripts/validate_survival_map.py` → 数字与 SSOT 逐项一致
5. `python scripts/validate_deep_model.py` → 页面与数据层双向核验
6. `python scripts/test_survival_map_injection.py` → 44/44 拦截

**跳过第 2 步的后果**：页面上会出现与数据层不一致的数字，而校验器会拦下来。

## 五、节气与经典出处

`data/节气经典_出处对照表.md` 提供逐条原句对照，24 节气全覆盖。

节气类条目的出处取自《素问·四气调神大论篇第二》的四时之令，
经典类条目的出处取自《素问》与《灵枢》各篇的篇名与原句。

**篇名与原句必须逐字比对**，不能凭印象转述——这是契约 A 对"经典研读博主"的要求，
也是「经典研读博主」位次工具化率最低（出处核验是纯手工）的原因。
